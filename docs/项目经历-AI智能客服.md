## 展开版（分点，按需增删）

- **提示词与上下文工程**：num_ctx 4096 窗口下按 `(num_ctx − num_predict − 64) × 1.4 × 0.85` 计算可用字符上限，条数 + 字符双约束裁剪历史，保证 System Prompt 与工具数据不被静默截断；显式 `think:false` 关闭默认思考模式，避免 token 预算被 thinking 占用导致正文为空。
- **Function Calling 工具注册中心**：工具以 JSON Schema 登记，两阶段循环（带 tools 请求 → 执行 → `assistant(tool_calls) + tool(result)` 回灌 → 不带 tools 二次生成）；订单工具支持单号 / 手机号 / 姓名三种入参、大小写空格容错、后 8 位后缀匹配。
- **实时天气数据链路**：服务端调用第三方天气 REST API（聚合数据 simpleWeather）拉取实时实况 + 未来 5 天预报 → 结构化解析为带时间戳的自然语言 → 以独立 system 消息注入上下文 → 约束模型「严格引用、缺失答暂无数据」。AppKey 仅在服务端内存，10 分钟缓存 + 调用埋点控制日额度（50 次 / 天）。
- **意图识别与规则旁路**：约 300 城天气词典 + 手机号 / 姓名 / 单号正则识别；确定性命中时服务端直接请求接口取数注入，规避 2B 小模型工具调用触发不稳定的问题；取数失败直接回友好文案，不交给模型编答案。
- **数据分析与效果度量**：SSE 埋点 `promptTokens` / `tokensPerSecond` / `trimmed` / `toolsUsed`，`/api/status` 输出会话数、消息数、天气缓存命中次数；10 分钟缓存策略控制外部天气 API 日额度（50 次 / 天）。
- **数据安全**：手机号前端脱敏（前 3 + `****` + 后 4）、AppKey 仅存 `.env` 与内存且日志脱敏、前端零第三方 CDN 依赖，可在离线 / 内网环境运行。

## 实时天气链路实录（2026-09-23 15:04 实测，可直接当面试材料）

请求 `queryWeather('苏州')` → 真实 HTTP 拉取 `https://apis.juhe.cn/simpleWeather/query`，返回：

```json
{
  "ok": true, "city": "苏州", "source": "juhe.simpleWeather", "cached": false,
  "realtime": { "weather": "阴", "temperature": "27", "humidity": "67",
                "direct": "东北风", "power": "4-5级", "aqi": "38" },
  "forecast": [ { "date": "2026-09-23", "low": "23", "high": "28", "weather": "多云转阴" }, ... 共 5 天 ]
}
```

服务端把它转成喂给模型的文本（带时间戳 + 引用约束）：

```
[天气数据·来自聚合数据实时接口 2026-9-23 15:04:59]
城市：苏州
实时：阴 27℃  湿度：67%  风向：东北风  风力：4-5级  空气质量：38
近三天：09-23 多云转阴 23~28℃ / 09-24 晴 24~29℃ / 09-25 多云转小雨 25~32℃
用户询问的是：实时
回答第一行必须先给出实时温度「27℃」这个数字，不得改动。
以上为接口返回的真实数据，回答时严格引用，禁止改动、推算或补充任何未给出的数值。
接口未给出的数据一律回答「暂无数据」，不许估算。
```

同一时刻的调用统计：`{"upstreamRequests":1,"cacheHits":0,"cacheSize":1,"cacheTtlMs":600000}` —— 这就是简历里「调用埋点 / 缓存命中」那条的真实出处。
